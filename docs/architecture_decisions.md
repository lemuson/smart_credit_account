# Архитектурные решения AI Service

## Main Backend как источник истины

AI Service не читает основную БД. Все пользовательские и продуктовые факты получаются через
контролируемые read-only API. Это сохраняет единое применение ACL и позволяет заменить Mock Backend
без изменения оркестратора.

## Нативный tool calling

Выбор инструмента выполняет Ollama/Qwen по JSON Schema. Ключевые слова и самописный intent-router не
используются. Исполнение всё равно контролирует приложение: allow-list, Pydantic, доверенная
идентичность, таймауты и конечное число раундов.

## RAG без LangChain

Для MVP достаточно небольших модулей loader/chunker/embedding/vector store/retriever. Прямой Chroma
API уменьшает число зависимостей и делает замену документа идемпотентной. RAG даёт только справочное
объяснение; числовые условия берутся из backend.

## Встроенный persistent ChromaDB

ChromaDB работает как библиотека и хранит данные в volume. Это проще для одного worker и локальной
демонстрации. Ограничение явно документировано: горизонтальное масштабирование потребует сетевого
векторного хранилища.

## Один worker для порядка

Prefetch и concurrency равны 1. Это осознанный MVP-компромисс, который предотвращает перемешивание
ответов. План масштабирования описан в `reliability.md`.
