# Кредитный кабинет — Vue 3

Vue 3 Composition API, Vite, Lucide. Тёмный адаптивный интерфейс по эскизу: верхняя навигация без бокового списка продуктов и баланса.

## Разработка

```sh
cd frontend
npm ci
npm run dev
```

Открыть http://localhost:5173. Vite проксирует `/api` на `http://127.0.0.1:8000`.
Для другого backend: `API_TARGET=http://localhost:8001 npm run dev`.

```sh
npm run build
npm test
```

## Страницы и сценарии

- `/#home`: главная, заявки, переход к финансированию, рекомендации из backend.
- `/#calculator`: цель, сумма, срок, фильтрация реального каталога, предварительный аннуитетный платёж, серверный график, создание черновика.
- `/#loans`: заявки со статусами, поиск и фильтр, действующие и закрытые кредиты. У сотрудника — очередь обработки.
- `/#assistant`: локальный справочный чат. AI Service в проекте не подключён; это явно отмечено в интерфейсе.
- Вход и регистрация клиента; редактирование профиля компании через кнопку справа в шапке.
- Заявка: компания, финансы, документы PDF/PNG/JPEG, подтверждение и отправка; запросы на уточнение и повторная отправка.
- Сотрудник: взять заявку, изучить досье и документы, запросить уточнение, запустить проверки ФНС/БКИ, отклонить или передать в автоматический анализ. Backend сам принимает решение.
- Одобрение: условия, график, принятие или отказ, просмотр структурированного договора, демо-подпись кодом `123456`.

JWT хранится в `sessionStorage`, передаётся через Bearer. При истечении сессии интерфейс запрашивает повторный вход. Все изменения используют `expected_version`; после загрузок, удалений и операций досье перечитывается. API-контракты backend не менялись. Роль ADMIN использует отдельные backend API/CLI, этот интерфейс предназначен для CLIENT/BANK_OFFICER.

## Браузерная проверка

Нужны установленный Google Chrome, работающий backend и созданный каталог продуктов. Тест регистрации создаёт синтетического клиента и заявку в текущей БД; используйте тестовый стенд. По умолчанию сохраняет PNG в `/tmp`; путь можно изменить через `TEST_ARTIFACT_DIR`.

```sh
TEST_BASE_URL=http://localhost:8080 node tests/browser-smoke.mjs
```

`CHROME_PATH` позволяет указать собственный исполняемый файл браузера. Тест проверяет регистрацию, калькулятор, компанию, финансовые поля, три загрузки документов, отправку, список заявок, справочный чат и отсутствие горизонтального переполнения на мобильном экране.

Полный цикл продолжает заявку клиента из первого теста. Создайте отдельного тестового сотрудника через CLI из README корня. У клиента и сотрудника должны быть одинаковые тестовые пароли для этого сценария:

```sh
TEST_BASE_URL=http://localhost:8080 \
TEST_CLIENT_EMAIL='<почта из результата browser-smoke>' \
TEST_OFFICER_EMAIL='<тестовый сотрудник>' \
TEST_PASSWORD='<тестовый пароль>' \
node tests/credit-flow.mjs
```

Полный сценарий: назначение сотрудника → запрос уточнения → ответ клиента → проверки ФНС/БКИ → скоринг → график → предложение → договор → демо-подпись. Тестовые пользователи и заявки остаются в БД. Реальные деньги и подпись не используются.
