# Умный кредитный кабинет предпринимателя

Клиентский кабинет и рабочее место кредитного сотрудника. Vue 3 + Vite, FastAPI, PostgreSQL 17. Интерфейс по ТЗ и эскизу: тёмная тема, верхняя навигация, главная, калькулятор, кредиты и справочный чат.

## Запуск из корня

Нужны Docker и Docker Compose 2.20+.

```sh
./start.sh
```

Кабинет: **http://localhost:8080**. API / Swagger: http://localhost:8000/docs.
При первом запуске скрипт создаёт `backend/.env` с независимыми случайными секретами PostgreSQL, JWT и AI. В существующий файл добавляется только отсутствующий `AI_SERVICE_TOKEN`. При наличии `.env` можно запускать напрямую:

```sh
docker compose up --build -d
```

Общий Compose запускает PostgreSQL → миграции → базовые данные → API → Nginx с Vue, а также RabbitMQ, backend AI bridge и AI worker. AI worker обращается к основному API; mock backend в этом запуске не используется. Nginx проксирует `/api` на backend, поэтому отдельная настройка CORS не нужна. PostgreSQL и API имеют healthcheck; данные остаются в существующем volume `smart-credit_postgres_data`.

Для другого порта: `FRONTEND_PORT=8090 ./start.sh`.

## Первый вход

При первом запуске автоматически создаются демонстрационные учётные записи:

| Пользователь | Email | Пароль |
| --- | --- | --- |
| Клиент | `client@example.com` | `Demo-credit-123!` |
| Кредитный сотрудник | `officer@example.com` | `Demo-credit-123!` |
| Администратор | `admin@example.com` | `Demo-credit-123!` |

Это тестовые учётные данные для локального учебного стенда.
Клиент получает профиль ООО «Демо Бизнес» (ИНН `7700000009`), финансовые сведения и черновик заявки. В каталоге три демонстрационных продукта: развитие бизнеса, оборотный капитал и оборудование. Для подачи черновика загрузите обязательные документы.

Загрузка выполняется **один раз на базу данных**, после миграций. Отметка `demo-data-v1` хранится в таблице `seed_runs` в том же постоянном volume. Повторные `up`, `start`, пересоздание контейнеров и сборка образов не добавляют дубликаты и не восстанавливают удалённые записи. Изменённые пароли, роли, профили и продукты сохраняются. Уже существующие email и одноимённые продукты при первой загрузке используются без перезаписи; профиль и черновик создаются только для нового демо-клиента. При совпадении email действует прежний пароль этой учётной записи.

Все записи и отметка фиксируются одной транзакцией. Ошибка откатывает загрузку целиком, следующий запуск может повторить её; параллельные запуски защищены уникальным ключом отметки. Миграции продолжают выполняться при обновлениях приложения.

Можно также зарегистрировать своего клиента через «Личный кабинет» → «Зарегистрироваться» или создать дополнительного сотрудника:

```sh
docker compose exec api python -m app.cli create-user --email officer2@example.com --role BANK_OFFICER
```

Войдите как кредитный сотрудник через тот же интерфейс. Сотруднику доступна очередь, досье, запрос уточнений, внешние демо-проверки и автоматический кредитный анализ. После одобрения клиент принимает предложение, проверяет договор и подтверждает оформление демо-кодом `123456`.

```sh
docker compose ps
docker compose logs --tail=100 frontend api migrate seed-data
docker compose stop
docker compose start
```

`docker compose down` сохраняет БД. Не добавляйте `-v`, если данные нужны.

## Разработка и проверка

```sh
cd frontend
npm ci
npm run dev
npm run build
npm test
```

Vite открывается на http://localhost:5173 и проксирует запросы на backend :8000.

[Frontend: экраны, архитектура и браузерные проверки](frontend/README.md).
[Backend: запуск, архитектура, API и тестирование](backend/README.md).
[Интерактивная HTTP-коллекция](backend/examples/credit-flow.http).

Чат подключён к AI Service: запрос сохраняется в backend, уходит через RabbitMQ и возвращается в интерфейс после сохранения ответа. Для генерации нужна работающая Ollama на хосте с моделями `qwen2.5:7b-instruct` и `qwen3-embedding:0.6b`; подготовка описана в [AI README](ai/README.md). Модели при запуске кабинета автоматически не скачиваются. Для другой установленной модели задайте `OLLAMA_LLM_MODEL` в `backend/.env`, для другого сервера — `OLLAMA_BASE_URL` (адрес должен быть доступен из контейнера). На macOS адрес по умолчанию — `http://host.docker.internal:11434`.

После подготовки моделей можно проиндексировать справочную базу:

```sh
docker compose exec ai-worker python -m scripts.ingest
```

База `ai/knowledge_base` содержит демонстрационные материалы mock-стенда; перед использованием RAG для конкретного каталога обновите продуктовые материалы. Актуальные условия AI получает через read-only API основного backend. Без доступной модели запрос завершится ошибкой; интерфейс не подменяет AI локальными заготовками.

Проверки, решение и оформление демонстрационные: реальных запросов в ФНС/БКИ, электронной подписи и банковского перевода нет. Итоговые суммы, ставки и графики рассчитывает backend.
