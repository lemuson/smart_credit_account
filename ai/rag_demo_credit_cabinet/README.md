# Демонстрационная база знаний для AI Service / RAG

**Назначение:** тестирование retrieval + генерации ответов Qwen в проекте «Умный кредитный кабинет предпринимателя».

## Содержимое

- `documents/KB-01_границы_базы_знаний.txt` — приоритет Backend Tools над учебным RAG.
- `documents/KB-02_порядок_подачи_заявки.txt` — учебный процесс и значение статусов.
- `documents/KB-03_учебный_перечень_документов.txt` — пример комплекта ИП и ООО.
- `documents/KB-04_залог_и_обеспечение.txt` — залог и ограничения признака has_collateral.
- `documents/KB-05_выручка_кредитная_история_и_сроки.txt` — основные термины анкеты.
- `documents/KB-06_демо_ml_оценка_и_what_if.txt` — значение синтетического ML-скоринга.
- `documents/KB-07_вопросы_ответы_и_ограничения.txt` — FAQ и безопасное отсутствие ответа.
- `evaluation/rag_eval_questions.md` — проверочные вопросы; **не индексировать**, чтобы избежать утечки ответов.

## Как подключить

1. Изучить реальный ingestion pipeline AI Service, конфигурацию Chroma collection, пути и Docker volume. Не предполагать заранее, что нужный путь существует.
2. Добавить **только семь TXT-файлов из `documents/`** в настроенный источник индексации (или явно передать их пути поддерживаемому loader). TXT выбран для максимальной совместимости; не индексировать README и каталог `evaluation`.
3. Проверить используемую embedding model и что runtime читает ту же коллекцию Chroma, куда ingestion пишет chunks.
4. Запустить **существующую команду индексации проекта**; точную команду найти в README/CLI репозитория, а не придумывать.
5. Проверить число chunks (`>0`), метаданные источников (`source` или эквивалент), дедупликацию и retrieval по отдельным документам.
6. Проверить сохранение Chroma после безопасного перезапуска контейнера без удаления volume.
7. Прогнать вопросы из `evaluation/` сначала напрямую к retriever, потом через реальную цепочку Backend → RabbitMQ → AI Service → Ollama → Backend.

## Правила использования

**Все документы учебные и полностью искусственные.** Не размещать их под видом официальных банковских материалов; не публиковать их как обязательные требования или условия Альфа-Банка.

Взаимодействие с Backend остаётся главным источником реальных продуктовых и персональных сведений:
- профиль предпринимателя — `get_user_profile`;
- актуальные кредитные продукты — `search_credit_products`, `get_product_details`;
- обязательные документы продукта — `get_required_documents`;
- статус заявки — `get_application_status`;
- проверка заявки — `validate_application`.

RAG объясняет понятия и учебные процедуры. Не подменять результаты Backend статическими примерами. Источники следует брать только из фактических retrieval metadata; наличие файла в ZIP не доказывает его использование в ответе.

## Версии

Набор: `rag-demo-1.0`. Формат TXT / UTF-8. Документы имеют постоянные ID `KB-01`...`KB-07`, по которым удобно проверять цитирование. При изменении содержимого следует обновлять версию корпуса и переиндексировать изменённые источники без накопления дублей.
